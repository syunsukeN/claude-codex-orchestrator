# RC2評価チェックリスト

## ゴール

最小のmediumリスクワークフローが実プロジェクトで使えるか、既知の誤りを検出できるかを判断します。

## 準備

- [ ] `framework.lock`のフレームワークversionとcommitを記録した。
- [ ] サンプルアプリの開始revisionを記録した。
- [ ] Codexが管理`AGENTS.md`と導入済みSkillを認識した。
- [ ] Claudeが管理`CLAUDE.md`インポートと導入済みSkillを認識した。
- [ ] 境界値または認可条件を少なくとも1つ含む、小さなmediumリスク挙動変更を選んだ。

## 必須証拠

- [ ] 曖昧な要求から、人間が承認したテスト可能なFeature Change Specを作れた。
- [ ] 全ACを少なくとも1つのWork Itemへ割り当てた。
- [ ] 全ACが受入テストのソースに含まれている。
- [ ] 新しい受入テストが実装前に意図した理由で失敗した。
- [ ] 実装後に設定された機械検査が成功した。
- [ ] 人間レビューと手動動作確認が成功した。
- [ ] 独立Verifierが、意図的に入れたSpec・テスト・実装の不整合を少なくとも1件検出した。
- [ ] Task Closure Noteがsource revision、差分、検証証拠と一致した。
- [ ] Closure後にdoctorが成功した。

## 人間の負担

1つ選び、最も大きな負担を書きます。

- [ ] 次回もそのまま使いたい。
- [ ] 具体的な修正後なら使いたい。
- [ ] 負担が大きく、次回は使いたくない。

## 指摘の記録

各指摘へ、工程、確認できる証拠、重要度、回避方法、反映候補、プロジェクト固有かフレームワーク共通かを記録します。作業続行できない場合を除き、実験途中で導入済みスナップショットを編集しません。
